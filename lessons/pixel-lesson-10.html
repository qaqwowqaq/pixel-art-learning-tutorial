LESSON 10 · ADVANCED

PIXEL PERFECT进阶 · 进引擎：像素完美

辛苦画的像素，进了引擎可能全毁在两件事上：非整数缩放，和亚像素抖动。

CONCEPT 01 — INTEGER SCALING

整数缩放

像素游戏内部跑在一个低分辨率画布上（比如 320×180），再放大铺满屏幕。放大倍数必须是整数（2×、3×、4×…）。一旦用了 2.5× 这种非整数缩放，就有一部分像素被放成 2 格、另一部分放成 3 格——同一张图里像素大小不一，移动时还会忽大忽小地"抖"。

下面左边是干净的 ×3 整数缩放，每个像素都是规整的正方块；右边 ×3.5，看那些忽宽忽窄、忽高忽矮的格子——这就是非整数缩放的硬伤。

✓ ×3 整数（均匀）
✗ ×3.5 非整数（不均匀）
CONCEPT 02 — SUB-PIXEL SHIMMER

像素完美相机与亚像素抖动

更隐蔽的坑：角色以非整数速度移动（比如每帧 0.35 像素），如果引擎不把位置对齐到像素网格，边缘像素会在帧与帧之间反复"借位"，整条轮廓抖动、爬行（shimmer / crawling）——就像第三课的"像素沸腾"，但这次是移动造成的。

解法：用像素完美相机，把相机和精灵的位置在渲染前吸附到整数像素。下面让小球横向移动，按住 像素对齐 开关切换感受：

PIXEL_PERFECT.exe
设置 / SETTINGS
移动速度 / SPEED 0.40 px/帧
关掉「像素对齐」：小球以非整数速度移动时，边缘开始发糊、抖动。打开它，边缘恢复脆硬、只做整像素跳进。
CONCEPT 03 — IMPORT SETTINGS

导入设置：把过滤关成"最近邻"

素材导入引擎时，纹理过滤必须设成最近邻 / 点采样（Nearest / Point），绝不能用默认的双线性（Linear / Bilinear）——否则像素边缘会被引擎自动模糊，第一课讲的硬边方块全没了。这是新手最常见、也最容易漏的一步。

配套要关掉的几项：Mipmap（多级渐远纹理，会让缩小后发糊）、纹理压缩（会污染纯色），以及把图集的 filter 也设为点采样。各引擎的位置：Godot 在导入面板把 Filter 设 Off / 在项目设置里开 Snap 2D Transforms to Pixel；Unity 把纹理 Filter Mode 设 Point、Compression 设 None，并加 Pixel Perfect Camera 组件；GameMaker 关掉 Interpolate colours。

CONCEPT 04 — ATLAS & AUTOTILE

精灵图集与自动连接

为了性能，引擎会把许多小图打包进一张大图——精灵图集 / 纹理图集（atlas），一次性上传 GPU。但有个陷阱：漏色（texture bleeding）——采样到了相邻贴图的边缘像素，于是精灵边上出现一条不该有的细线。

图集里每块之间留 1～2px 间距（padding），并把边缘像素向外延伸一圈（extrude），就能根治漏色。

瓦片地图同理：第四课手搓的自动连接，在引擎里是现成功能——Godot 的 TileMap + Terrain、Unity 的 Tilemap + Rule Tile、或直接导入 Tiled 工程。你只管刷"这片是水"，墙角河岸引擎自动接好。记得给 tileset 也留 padding/extrude。

一句话工作流：低分辨率设计 → 整数缩放铺屏 → 相机/精灵吸附像素 → 过滤设最近邻、关 mipmap → 图集留 padding。这五条做到，你的像素在引擎里就和在 Aseprite 里一样脆。
